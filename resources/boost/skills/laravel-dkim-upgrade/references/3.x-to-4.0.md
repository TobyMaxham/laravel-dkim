# Upgrade laravel-dkim from 3.x to 4.0

Agent instructions. Work through the steps in order. Steps marked with **ASK** need a decision of the user.
Background for every step: [UPGRADING.md](https://github.com/TobyMaxham/laravel-dkim/blob/main/UPGRADING.md#from-3x-to-40).

## Step 1: Check the requirements

4.0 requires PHP 8.3+, Laravel 12 or 13 and `ext-openssl`.

- Check `php -v`, the `php` constraint and `laravel/framework` in `composer.json`.
- If the app runs Laravel 9, 10 or 11 or PHP < 8.3: **stop** and tell the user to stay on `tobymaxham/laravel-dkim:^3.0` (no longer maintained) or to upgrade Laravel / PHP first. Do not upgrade Laravel as part of this task.

## Step 2: Find all usages

Search the app (not `vendor/`) and keep the results for the next steps:

```sh
grep -rn "laravel-dkim\|LaravelDkimSigner" config/ app/ routes/ tests/ bootstrap/ --include="*.php" 2>/dev/null
grep -rn "MAIL_DKIM_" .env.example config/ 2>/dev/null
grep -rnE "DkimSigner|ApplyDkimSignature|signMessage|getSigner" app/ tests/ --include="*.php" 2>/dev/null
```

Note: a published `config/laravel-dkim.php`, its senders, `dkim_identity`, and custom code that calls `DkimSigner` or extends `ApplyDkimSignature`.

## Step 3: Update the package

```sh
composer require tobymaxham/laravel-dkim:^4.0 -W
```

If composer fails because of other packages, report the conflict to the user. Do not remove or downgrade other packages without asking.

## Step 4: Update a published config

Only if `config/laravel-dkim.php` exists in the app. Keep all existing values.

- Add the new global keys:

  ```php
  'dkim_fallback' => env('MAIL_DKIM_FALLBACK', 'skip'),
  'dkim_on_error' => env('MAIL_DKIM_ON_ERROR', 'throw'),
  ```

- 3.x chose a sender by its name (the From address with `.` replaced by `_`, e.g. `info@example_com`). 4.0 chooses it by `dkim_domain` and `addresses`. For every sender:
  - make sure `dkim_domain` is set to the domain of the From addresses it signs,
  - if the name is an address like `info@example_com`, add `'addresses' => ['info@example.com']` and rename the key to a plain name (e.g. `example_com`). Update `MAIL_DKIM_DEFAULT_SENDER` if it pointed to the old name.
- If there is more than one sender, **ASK** the user to confirm which From addresses each sender must sign. Show them the table: From address -> sender.
- Only one sender may have no `dkim_domain`. A sender without `dkim_domain` signs every other From domain.
- Remove `dkim_identity` (never used).
- `dkim_algo` must be `rsa-sha256`.

## Step 5: ASK about the fallback

In 3.x a mail whose From address matched no sender was signed with the default sender, also for other domains. In 4.0 it is sent without signature.

Look for From addresses of other domains in the app (`->from(`, `from:`, `MAIL_FROM_ADDRESS`, notifications). Then ask the user to choose:

| Option | `.env`                       | Effect                                                    |
|--------|------------------------------|-----------------------------------------------------------|
| **a**  | nothing                      | Mails without matching sender are not signed. Recommended. |
| **b**  | `MAIL_DKIM_FALLBACK=default` | Same as 3.x, sign them with the default sender.           |
| **c**  | `MAIL_DKIM_FALLBACK=fail`    | Throw an exception, the mail is not sent.                 |

Recommend **a**: a signature with a domain other than the From address does not help with DMARC. Add the chosen variable to `.env.example` and to the report.

## Step 6: Remove `dkim_identity`

Remove `MAIL_DKIM_IDENTITY` from `.env.example` and tell the user to remove it from the `.env` files. It was never used.

## Step 7: Fix the code

Only if step 2 found custom code:

- `app(DkimSigner::class)->signMessage($message, $sender)` becomes `app(DkimSigner::class)->sign($message)`. It returns the signed message or `null`. The sender is chosen from the From address.
- `getSigner()` is removed.
- Classes that extend `ApplyDkimSignature` get `DkimSigner $signer` in the constructor.
- `catch (RuntimeException $e)` still works. The new exceptions are `TobyMaxham\LaravelDkimSigner\Exceptions\InvalidDkimConfiguration` and `NoMatchingSender` (both extend `DkimException`).

## Step 8: Check the config and the keys

```sh
php artisan dkim:check
```

Report the status of every sender. `CONFIG_ERROR` and `KEY_ERROR` are caused by the config, fix them (the details name the config key). For DNS errors, tell the user; do not create new keys or selectors without asking.
If signing is disabled locally, the command still checks the config and the keys. If the keys exist only on the servers, run `php artisan dkim:check --no-dns` there or tell the user to run it.

## Step 9: Tests

- Tests that expect the message `Some configuration is missing to add DKIM signature!` must expect `InvalidDkimConfiguration` now.
- Tests that rely on mails of other domains being signed need `dkim_fallback=default` (if the user chose **b**) or must be changed.
- Run the test suite and static analysis. Fix failures caused by the upgrade, report others.

## Step 10: Report

Use the report format of [SKILL.md](../SKILL.md#3-report). Always include:

- the chosen fallback and the `.env` values for every environment,
- the table From address -> sender,
- that `MAIL_DKIM_IDENTITY` can be removed from all `.env` files.
